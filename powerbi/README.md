# Feed Ranking Launch Review (Power BI)

This folder is a **Power BI Project (PBIP)**, Power BI's text-based, Git-friendly format. Everything is generated by
`python -m sei.powerbi` from the analysis outputs. Do not hand-edit the files.

```
powerbi/
├── Feed_Ranking_Launch_Review.ipynb             ← Fabric: import this notebook and Run all
├── Feed_Ranking_Launch_Review.pbip              ← Power BI Desktop (Windows): open this
├── Feed_Ranking_Launch_Review.SemanticModel/    model.bim (32 tables, 15 relationships, 30 DAX measures) + .platform
├── Feed_Ranking_Launch_Review.Report/           report.json (11 pages) + .platform
├── Feed_Ranking_Launch_Review_data.xlsx         all tables as one workbook (web-app upload fallback)
├── Feed_Ranking_Launch_Review_Theme.json        palette (arm colours match every chart in the project)
├── data/                                        star schema + result tables (CSV, UTF-8)
└── measures.dax                                 every measure, for reference or copy/paste
```

**Where the data comes from:** the semantic model reads each CSV straight from this public GitHub repo
(`https://raw.githubusercontent.com/<DataPath><table>.csv`). It needs no file paths or gateway, and refreshes in both
Desktop and the Power BI Service. Re-running the pipeline and pushing to `main` updates the dashboard on its next refresh.

## Option 0: Fabric notebook deploy (full 11-page report, no Git, works on a Mac)

Use this when your organisation blocks Git integration. Needs a workspace on a Fabric trial or capacity.

1. In the workspace: **Import → Notebook → From this computer** → `powerbi/Feed_Ranking_Launch_Review.ipynb`.
2. Open the notebook → **Run all**. It creates (or updates) the **Feed Ranking Launch Review** semantic model and report.
   If you deployed the older `SEI_Dashboard` items, you can delete them and the old `deploy_to_fabric` notebook.
3. If the last cell reports a credentials error: semantic model **… → Settings → Data source credentials →
   Edit credentials → Anonymous / Public → Sign in**, then re-run the last cell.

## Option A: Power BI web app via Git sync (full 11-page report, works on a Mac)

Requires a workspace on **Fabric capacity** (a Fabric trial works), Premium, or Premium Per User.
Check under *Workspace settings → License info*. A plain Pro trial workspace does not offer Git integration.

1. **GitHub token:** github.com → *Settings → Developer settings → Personal access tokens → Fine-grained tokens →
   Generate*. Repository access: only `social-engagement-intelligence-pro`. Permissions: **Contents: Read and write**.
2. **Connect:** in your workspace, *Workspace settings → Git integration → GitHub → Add account* (paste the token and
   the repo URL `https://github.com/NirmalKumar31/social-engagement-intelligence-pro`) → **Connect**.
3. **Branch** = `main`, **Git folder** = `powerbi` → *Connect and sync*. The workspace now shows the
   **Feed Ranking Launch Review** semantic model and report.
4. **Credentials (one time):** open the semantic model's *Settings → Data source credentials → Edit credentials* →
   Authentication method **Anonymous**, privacy level **Public** → Sign in.
5. Semantic model → **Refresh now**. Open the **Feed Ranking Launch Review** report.

> Workspace settings are blocked? Your tenant admin must enable *"Users can synchronize workspace items with
> GitHub repositories"* in the Admin portal.

## Option B: Power BI web app, Excel upload (any license, manual report)

1. *Import → Report, Paginated Report or Workbook → From this computer* → `Feed_Ranking_Launch_Review_data.xlsx`.
2. *Workspace settings → General → Data model settings →* allow editing data models in the service.
3. Semantic model → **Open data model** → create relationships: `fact_daily[date]` → `dim_date[date]`, and `arm` →
   `dim_arm[arm]` from `fact_daily`, `fact_user`, `metric_results`, `segment_results`, `daily_lift`, `km_survival`,
   `impact_fan`, `impact_distribution`, `topic_exposure_by_arm`, `content_exposure_summary`, `sequential_monitoring`.
4. **New measure** → paste from `measures.dax`. Then **Create report** and build the pages listed [below](#pages).

## Option C: Power BI Desktop (Windows, or a Windows VM on a Mac)

Open `Feed_Ranking_Launch_Review.pbip` → **Refresh**. (If Desktop asks, enable *Options → Preview features → Power BI Project
(.pbip) save option*.) To read local files instead of GitHub:
`python -m sei.powerbi --source local --data-folder "C:\SEI\powerbi\data\"`. To turn it into a single file,
use *File → Save as → .pbix*.

## Data model (star schema)

| Table | Grain | Rows | Notes |
|---|---|---|---|
| `dim_date` | day | 42 | pre-period (-14..-1) + experiment (0..27), weekday / weekend |
| `dim_arm` | arm | 3 | label, sort order, colour |
| `fact_daily` | date × arm × age × region × device × account type | ~28K | additive sums + `users_assigned` denominator |
| `fact_user` | user | 60K | pre/post metrics, churn, churn-risk score + tier, CATEs, policy arm |
| `metric_results`, `segment_results`, `daily_lift`, `km_survival`, `impact_*`, … | analysis outputs | small | linked to `dim_arm` |

Relationships run many-to-one from each fact or result table to `dim_arm` (and `fact_daily` → `dim_date`), with
single-direction filtering. Every engagement measure is **per assigned user-day** (intent-to-treat), so it stays correct
under any slicer combination: `DIVIDE(SUM(numerator), SUM(fact_daily[users_assigned]))`.

## Pages

| # | Page | What it answers |
|---|---|---|
| 1 | Overview | The decision banner, six insight cards (novelty, retention, revenue, personalisation, early warning, content), headline charts |
| 2 | Decision & Guardrails | Status chip per arm, guardrail matrix (observed change, allowed harm, PASS/FAIL), worst-case harm vs margin |
| 3 | Results Snapshot | KPI cards, daily minutes, lift by day (novelty decay), metric scorecard |
| 4 | Experiment Scorecard | Wins/harms, lift by metric, CUPED MDE curve, confidence intervals |
| 5 | Engagement Trends | Segment slicers × daily lift, DAU, friend interactions, revenue |
| 6 | Segment Deep-Dive | Churn and minutes effects by age and region, segment verdicts |
| 7 | Retention & Lapse Risk | Time to first 7-day lapse, lapse drivers (SHAP), nudge value by share targeted |
| 8 | Personalisation | Policy values, uplift gain curves, observed uplift by predicted decile (per arm) |
| 9 | Content Health (Scenario) | Topic exposure, negative share, diversity under ASSUMED ranker weights; sentiment benchmark |
| 10 | Revenue Scenarios | 12-month fan, value distribution, all persistence scenarios, sensitivity |
| 11 | Creator Virality (Real) | Real-data SHAP drivers, descriptive playbook, weekly trend |

Every page carries a synthetic-data label and a footer with the run commit and generation date. All narrative text is
generated from the results (`sei/narrative.py`); none is typed into the report.

## Troubleshooting

- **Sync error on the report:** the semantic model (`model.bim`) is standard TMSL and is the robust part. If the
  generated `report.json` is rejected, delete `Feed_Ranking_Launch_Review.Report/` from the repo, sync the model alone, then
  build the pages from the table above.
- **Refresh fails with "credentials":** redo step 4 of Option A (Anonymous / Public).
- **Forked the repo?** Regenerate with `python -m sei.powerbi --github-path "<you>/<repo>/main/powerbi/data/"`.
