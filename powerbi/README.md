# Power BI dashboard

This folder is a **Power BI Project (PBIP)**, Power BI's text-based, Git-friendly project format. Everything is
generated by `python -m sei.powerbi` from the analysis outputs. Do not hand-edit the CSVs.

```
powerbi/
├── SEI_Dashboard.pbip               ← open this
├── SEI_Dashboard.SemanticModel/     model.bim: 31 tables, 12 relationships, 30 DAX measures
├── SEI_Dashboard.Report/            report.json: 9 pages, 63 visuals
├── data/                            star schema + result tables (CSV, UTF-8)
├── SEI_Theme.json                   palette (arm colours match every other chart in the project)
└── measures.dax                     every measure, for reference or copy/paste
```

## Open it (Windows, Power BI Desktop)

1. **Turn on PBIP support once:** *File → Options and settings → Options → Preview features →
   "Power BI Project (.pbip) save option"* ✔, then restart Desktop. (Recent Desktop builds have it on by default.)
2. Copy the whole repo to the Windows machine, e.g. `C:\SEI\`.
3. **Point the model at the data folder.** Either:
   - regenerate with your path: `python -m sei.powerbi --data-folder "C:\SEI\powerbi\data\"`, **or**
   - open the project, then *Home → Transform data → Edit parameters → DataFolder* = the full path to
     `powerbi\data\` **including the trailing backslash**.
4. Open `SEI_Dashboard.pbip` → **Refresh**.
5. Optional: *View → Themes → Browse for themes →* `SEI_Theme.json`.

> On a Mac, run Desktop in a Windows VM (Parallels or UTM), or import the CSVs into the Power BI Service web app
> and rebuild the visuals with the measures from `measures.dax`. Power BI Desktop itself is Windows-only.

## Data model (star schema)

| Table | Grain | Rows | Notes |
|---|---|---|---|
| `dim_date` | day | 42 | pre-period (-14..-1) + experiment (0..27), weekday / weekend |
| `dim_arm` | arm | 3 | label, sort order, colour |
| `fact_daily` | date × arm × age × region × device × account type | ~28K | additive sums + `users_assigned` denominator |
| `fact_user` | user | 60K | pre/post metrics, churn, churn-risk score + tier, CATEs, policy arm |
| `metric_results`, `segment_results`, `daily_lift`, `km_survival`, `impact_*`, … | analysis outputs | small | linked to `dim_arm` |

Relationships run many-to-one from each fact or result table to `dim_arm` (and `fact_daily` → `dim_date`), with
single-direction filtering. Every engagement measure is **per assigned user-day** (intent-to-treat), so it stays correct
under any slicer combination: `DIVIDE(SUM(numerator), SUM(fact_daily[users_assigned]))`.

## Pages

| # | Page | What it answers |
|---|---|---|
| 1 | Executive Summary | KPI cards, daily minutes by arm, novelty decay, full metric scorecard |
| 2 | Experiment Scorecard | Wins/harms, lift by metric, CUPED MDE curve, CIs and variance reduction |
| 3 | Engagement Trends | Segment slicers × daily lift, DAU, friend interactions, revenue |
| 4 | Segment Deep-Dive | Churn and minutes effects by age/region/device/…, with verdicts |
| 5 | Retention & Churn Risk | Kaplan-Meier, SHAP drivers, profit curve, users by risk tier |
| 6 | Personalisation (HTE) | Policy values, Qini curves, CATE calibration by decile |
| 7 | Content & Responsible AI | Topic exposure, negativity share, diversity, sentiment benchmark |
| 8 | Business Impact | 12-month Monte Carlo fan, value distribution, sensitivity |
| 9 | Creator Virality | Real-data SHAP drivers, playbook by channel/weekday/media, weekly trend |

## If the report fails to open

The semantic model (`model.bim`) is standard TMSL and is the robust part. If your Desktop version rejects the
generated `report.json` layout, delete `SEI_Dashboard.Report/report.json`, open the project (you get a blank
canvas on top of the full model and measures), and rebuild the pages from the table above. Every visual is a
standard visual bound to the listed measures and columns.
