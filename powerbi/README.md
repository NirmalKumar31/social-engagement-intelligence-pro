# Feed Ranking Launch Review (Power BI)

A Power BI project (PBIP) generated by `python -m sei.powerbi`. Don't edit the files by hand; regenerate them.

```
Feed_Ranking_Launch_Review.ipynb             Fabric notebook: import and Run all
Feed_Ranking_Launch_Review.pbip              Power BI Desktop (Windows)
Feed_Ranking_Launch_Review.SemanticModel/    model: 32 tables, 15 relationships, 30 measures
Feed_Ranking_Launch_Review.Report/           report: 11 pages
Feed_Ranking_Launch_Review_data.xlsx         all tables in one workbook
Feed_Ranking_Launch_Review_Theme.json        colour theme
data/                                        CSVs the model loads
measures.dax                                 all measures
```

The model reads its CSVs from this GitHub repo, so it refreshes in Desktop and in the Power BI Service without a
gateway. Pushing new outputs to `main` updates the report on its next refresh.

## Opening it

**Fabric notebook (works on a Mac).** Needs a workspace on a Fabric trial or capacity.

1. In the workspace, choose *Import → Notebook → From this computer* and pick `Feed_Ranking_Launch_Review.ipynb`.
2. Open it and choose *Run all*. It creates or updates the semantic model and the report.
3. If the refresh cell fails on credentials, open the semantic model's *Settings → Data source credentials*, edit the
   Web source to *Anonymous* with privacy level *Public*, then re-run that cell and the last one.

**Git sync.** If your tenant allows GitHub sync: *Workspace settings → Git integration*, connect this repo, branch
`main`, folder `powerbi`. Then set the credentials as above and refresh.

**Excel upload (any licence).** Upload `Feed_Ranking_Launch_Review_data.xlsx`, create the relationships listed below,
paste the measures from `measures.dax`, and build the pages yourself.

**Power BI Desktop (Windows).** Open `Feed_Ranking_Launch_Review.pbip` and refresh. To use local CSVs instead of
GitHub, regenerate with `python -m sei.powerbi --source local --data-folder "C:\path\to\powerbi\data\"`.

## Model

| Table | Grain | Rows |
|---|---|---|
| `dim_date` | day | 42 |
| `dim_arm` | arm | 3 |
| `fact_daily` | date × arm × age × region × device × account type | ~28K |
| `fact_user` | user | 60K |
| result tables (`metric_results`, `segment_results`, `decision_guardrails`, …) | varies | small |

Fact and result tables relate many-to-one to `dim_arm` (and `fact_daily` to `dim_date`). Engagement measures are per
assigned user-day, so they hold up under any slicer. Control baselines use `REMOVEFILTERS(dim_arm)` so arm filters
don't blank them.

## Pages

1. Overview: decision, six key numbers, headline charts
2. Decision & Guardrails: status per arm, guardrail matrix
3. Results Snapshot
4. Experiment Scorecard
5. Engagement Trends
6. Segment Deep-Dive
7. Retention & Lapse Risk
8. Personalisation
9. Content Health (scenario under assumed ranker weights)
10. Revenue Scenarios
11. Creator Virality (real data)

All page text is generated from the results (`sei/narrative.py`).

## If something breaks

- Refresh fails on credentials: set the Web source to Anonymous / Public.
- The report won't load but the model does: delete the report and rebuild the pages on the model.
- Using a fork: regenerate with `python -m sei.powerbi --github-path "<you>/<repo>/main/powerbi/data/"`.
