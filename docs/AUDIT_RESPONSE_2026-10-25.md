## Per finding

### S01 Recommendation hard-coded despite failed guardrail (P1): addressed
- **Changed:** `sei/config.py` (`GUARDRAILS`, `SYNTHETIC_NOTICE`), new `sei/decision.py`, new `sei/narrative.py`, `sei/report.py`,
  `dashboard/app.py`, `sei/pbi_report.py`, README.
- **Rule:**
  - Primary metric must be a BH-significant win.
  - Each guardrail gets a one-sided non-inferiority test against a margin, Bonferroni-adjusted across 8 guardrail × arm comparisons.
  - States are PASS / FAIL / INCONCLUSIVE; INCONCLUSIVE is never treated as safe.
  - Arm states are LAUNCH / CONDITIONAL / DO NOT LAUNCH (critical vs standard guardrails).
  - Memo, Streamlit and Power BI text are generated from these states.
- **Synthetic notice:** shown on the memo, the Streamlit sidebar, every Power BI page header, and the README.
- **Checks:** six fixture tests cover all-pass, null primary, reversed primary, critical harm, inconclusive critical, and standard harm.
  The 3,000-user fixture correctly yields DO NOT LAUNCH, because its guardrails are inconclusive.
- **Open:** the margins were written after results were seen. This is disclosed everywhere they appear, but it cannot be undone retroactively.

### S02 Early-warning positives mostly already quit (P1): addressed
- **Changed:** `sei/retention.py`.
- **Task:** predict a 7-day lapse starting days 14–21 among users **active on day 13**.
- **Simulator benchmark:** 0 of 1,562 positives had already quit; 1,000 quit permanently later; 562 lapsed temporarily.
- **Baselines:** unweighted and class-weighted logistic are both shown. Weighting changes the Brier score (0.033 → 0.183), not AUC.
- **Deployed model:** chosen by training CV, which picked logistic.
- **Checks:** a future-perturbation test confirms features don't change; a test confirms the already-quit count is 0.
- **Open:** temporary lapses and permanent quits share one label. A reactivation-aware model would separate them.

### S03 Survival event/censoring inconsistent (P1): addressed
- **Endpoint:** time to the first fully observed 7-day lapse, censored at day 21 (the last start day with a complete window).
- **Added:**
  - Proportional-hazards test (p = 0.45 / 0.82).
  - RMST to day 21.
  - Person-time rate ratios.
  - A simulator-only Cox fit on the latent permanent-quit day.
- **Open:** no recurrence/reactivation model. The observable lapse endpoint dilutes the true permanent-quit effect (1.08 vs 1.17).

### S04 Always-valid guarantee not established (P1): qualified, not solved
- **Changed:** `sei/stats.py` docstring; `sei/experiment.py`.
- **Mixing scale:** now 5% of the **pre-period** control mean.
- **Null diagnostic:** the Gaussian toy simulation is replaced by re-randomizing real control users into two pseudo-arms, monitored daily on cumulative per-user averages (400 splits).
- **Wording:** the monitor is labeled an approximation everywhere; `p_always_valid` is renamed `p_mixture`.
- **Open:** no sequential method with a proven guarantee for this design, no guardrail or multi-arm monitoring rule, and no power analysis of the stopping rule.

### S05 Annual forecast mixes estimands, omits joint uncertainty (P1): largely addressed
- **Decomposition** (`sei/impact.py`): revenue per not-lapsed user-day (days 14–27, before each user's first lapse) × lapse survival.
- **Same endpoint as S03.**
- **Joint uncertainty:** both parameters come from the same user bootstrap (1,000 draws), with the control arm resampled once and shared across contrasts. The rev-vs-hazard correlation (≈ −0.01 / −0.07) and the cross-arm revenue-lift correlation (0.54) are reported.
- **Scenarios:**
  - Persistence: persist, half-decay, fade.
  - One-way sensitivity, including persistence.
  - A joint adverse stress case: −$94M, labeled an illustration.
- **Wording:** "share of draws" replaces "probability".
- **HTE outcome:** labeled an assumed utility score, not dollars.
- **Open:** the base lapse rate and persistence are untestable transport assumptions shown as scenarios. Model-form uncertainty beyond those scenarios is not quantified.

### S06 Campaign depth optimized on test labels, no no-send (P1): addressed
- **Selection:** depth is chosen on training out-of-fold predictions. A predefined break-even rule is also frozen. Both are evaluated once on test, with 500-draw bootstrap intervals.
- **No-send:** "Send to nobody" is a rule in the table and in the curve.
- **Dashboard:** now applies the break-even rule to out-of-fold scores and says "send to nobody" when value ≤ 0.
- **Regression test:** added for the adverse case.
- **Open:** the 18% save rate is an assumption until measured in a randomized nudge holdout. Risk ≠ persuadability.

### S07 CATE "ground truth" was a proxy (P1): addressed
- **New oracle** (`sei/oracle.py`): every user is re-simulated under all three arms with common seeds, 16 replications, under the exact HTE outcome definition. Per-user Monte Carlo error is about 6.
- **Validation reported** (`sei/hte.py`):
  - Spearman correlation.
  - RMSE, raw and noise-corrected.
  - Bias.
  - Decile calibration slope.
  - Oracle regret per policy.
- **Open:** per-user oracle noise is still sizeable. Group-level metrics are the reliable ones.

### S08 Power BI control baselines conflict with arm-label filters (P1): fixed in source, not live-tested
- **DAX:** every control-baseline measure now uses `CALCULATE(..., REMOVEFILTERS(dim_arm), dim_arm[arm] = "control")`. A test enforces it.
- **Open:** not executed in a semantic engine against pandas references; the audit's suggested slicer-matrix validation is still to do.

### S09 Declared ranges include broken configurations (P1): addressed
- **dtype handling:** uses pandas type predicates, so extension and pandas-3 strings, nullable ints and bools all work. Tested.
- **Versions:** NumPy floor raised to 2.0 (`np.trapezoid`); pandas `<4`. `make setup` installs `requirements-lock.txt`; `make setup-latest` installs the ranges.
- **Verified:** the Power BI export under pandas 3.1.0 / NumPy 2.5.4.
- **Open:** the full pipeline has not been run under the newest allowed versions of every package; CI uses the lock file.

### S10 CUPED relative lift denominator (P2): addressed
- **Estimand:** `rel_lift = adjusted diff / raw control mean`, with a delta-method SE that includes the covariance between the adjusted difference and the raw control mean.
- **Validation:** 95.3% coverage in 1,000 simulations.
- **Naming:** raw and adjusted means are kept separately named. `welch()` is documented as a Welch-SE large-sample z test and rejects fewer than 2 observations.

### S11 Policy comparison and Qini definitions (P2): addressed
- **Estimator:** Horvitz–Thompson with the known 1/3 design probability.
- **Comparisons:** paired bootstrap differences against blanket friend boost, plus the share of draws in which a policy beats it.
- **Curves:** renamed "cumulative uplift gain" with an origin point. The area ratio is labeled our own convention and returns `None` when undefined.
- **Policy tree:** trained on training-user predictions and evaluated on test as its own policy.

### S12 Virality temporal leakage/provenance (P2): addressed as far as data allows
- **Split:** on whole dates (≤ 2014-06-30 train, ≥ 2014-07-01 test).
- **Threshold:** 2,900 shares, from training articles only.
- **Ablation:** without the 12 `kw_*` / `self_reference_*` features, AUC is 0.691.
- **Wording:** "ordered retrospective benchmark"; the playbook is labeled descriptive.
- **Open:** feature availability at publication time cannot be verified from the UCI release.

### S13 Exposure harms built into the scenario (P2): addressed
- **Wording:** labeled a scenario under assumed weights in the memo, Streamlit, Power BI and the figure title.
- **Data:** the exposure pool is restricted to TweetEval **test** posts, which the sentiment model never trained on.
- **Sensitivity:** a 3 × 5 weight sweep is added. Negative share ranges 25–49%, driven by the assumed engagement weight.

### S14 Power BI semantics and refresh (P2): partly addressed
- **Arm identity:** `qini_curves` and `cate_deciles` are related to `dim_arm`, and the HTE page shows them per arm.
- **Narrative:** all page text is generated from results, so the "every age group" and "mostly novelty" claims are now computed sentences.
- **Deploy:** the notebook updates an existing semantic model and report rather than skipping them. A run manifest is written.
- **Open:**
  - Precomputed result tables still do not respond to daily-fact segment slicers; this is not yet labeled on each visual.
  - Refresh reads mutable `main` rather than a pinned commit.
  - Slicer behavior has not been tested in Desktop or Fabric.

### S15 Novelty asymptote unvalidated (P2): addressed
- **Intervals:** user-bootstrap (200 draws, shared control) for the asymptote, decay constant and observed week-1 / week-4 lifts.
- **Wording:** "fitted asymptote (extrapolated)" everywhere, with the observed week-4 lift shown alongside.
- **Open:** no model-form or window sensitivity; four weeks cannot establish 12-month persistence (hence the impact scenarios).

### S16 Engineering and tests (P2): largely addressed
- **Isolation and CI:**
  - `SEI_WORKDIR` and `SEI_N_USERS` isolate fixture runs.
  - `make fixture` and the GitHub Actions workflow (unit tests, download, full fixture pipeline, tests) are added.
- **Run manifest:** commit, dirty flag, package versions, config, stage list, and input and output hashes.
- **Tests:** 17 audit-regression tests, including a future-perturbation leakage test.
- **Runtime safeguards:**
  - Streamlit caches are keyed by file modification time.
  - The SQL helper can refresh its views.
  - Warning suppression is narrowed.
  - `--skip-nlp` refuses outputs from a different config.
- **Open:**
  - Outputs are not written to a staging directory and promoted atomically.
  - There is no real-data ingestion mode, so the project does not claim one.
  - External downloads are not pinned to a revision, though their hashes are recorded.
